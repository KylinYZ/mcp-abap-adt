# MCP ABAP ADT 性能与资源护栏设计

> 状态：代码与自动化验证已完成；真实 SAP DEV 已验证只读数量/响应限制、源码缓存、FIFO 队列和队列满拒绝，本地停滞端点已验证底层 HTTP 超时取消。长任务、提高并发后的共享会话和跨 SAP 版本表现仍待专项验证。该能力已随 npm 包 `@kylinyz/mcp-abap-abap-adt-api@0.4.0` 发布；MCP Registry 状态另行核验。

## 1. 背景与目标

当前服务是单进程 stdio MCP Server，`safe` 与 `legacy-full` 工具共享一个 stateful `ADTClient`。静态审查确认主要风险来自 SAP 远程请求、共享会话并发、进程内大对象生命周期、无界查询响应和同步日志，而不是本地 `switch` 分发开销。

本次改造遵循以下原则：

- 保留安全变更流程中的传输复核、源码漂移检查、写后语法检查、激活后校验和自动回滚。
- 保护覆盖 `safe` 与 `legacy-full` 全部工具，正常范围内不改变现有返回契约。
- 优先使用现有依赖和进程内简单结构，不引入 Redis、外部队列、数据库或新的基础设施。
- 超限请求明确拒绝，不静默截断，不让调用方误判结果完整性。
- 性能结论通过测试和真实 SAP 验证，不依据未经测量的微优化假设。

## 2. 不在本次范围

- 不重写全部 Handler 或消除全项目所有 `any`。
- 不解析、改写或优化用户提交的 SQL。
- 不实现通用游标分页、分布式缓存、多实例协调或持久化任务队列。
- 不删除安全工作流中的二次校验来减少 SAP 请求。
- 不自动重试非幂等写操作。
- 不自动删除安全审计日志。

## 3. 方案选择

采用“中央护栏，局部清理”方案：在现有服务器入口增加统一执行门控和底层 HTTP 超时；在查询 Handler、变更计划、源码缓存、确认挑战和日志类中增加局部边界。

不采用读写客户端分离作为第一版，因为约 100 个旧工具的状态属性需要重新分类，遗漏风险高。只有真实压测证明单并发读取成为瓶颈后，才评估使用 stateless clone 承载有界并发读取。

## 5. 统一 ADT 超时

`abap-adt-api` 的 `ADTClient` 构造参数原生支持 `ClientOptions.timeout`，因此服务器创建客户端时直接传入 `SAP_MCP_ADT_TIMEOUT_MS`。底层 Axios 会真正终止超时请求，不使用只能停止等待、无法取消网络请求的 `Promise.race`。

调试器等依赖内部为单次请求设置专用长超时的接口继续服从其显式请求级配置。写操作超时后结果可能未知，错误信息必须提示调用方先查询对象或计划状态，不得自动重试。

## 6. 工具执行门控

### 6.1 行为

所有 `CallToolRequestSchema` 请求统一经过参数和响应保护；实际使用共享 `ADTClient` 的操作进入一个进程内 FIFO 执行门控：

1. 有可用执行槽时立即执行。
2. 无执行槽且等待数量未达上限时排队。
3. 队列已满时不调用 ADT，返回结构化“服务繁忙”错误。
4. 请求完成、失败或抛出异常后必须释放执行槽并唤醒下一项。

门控覆盖 `safe` 与 `legacy-full` 中所有访问 SAP 的工具，包括 `logout`、`dropSession`、锁、写入、查询和读取。`applyAbapChange` 的用户确认等待在 gate 外进行，确认成功后完整 `workflow.apply`（包含复核、写入和自动回滚）在同一个 gate 内原子执行；纯本地 `getAbapChangeStatus` 与 `healthcheck` 不占 SAP 执行槽。默认单并发保证共享 Cookie、CSRF、session type 和锁生命周期不会交叉。

### 6.2 实现边界

新增一个小型 `ToolExecutionGate`，只负责计数、FIFO 排队和释放，不理解具体工具语义。服务器的原有分发逻辑移入门控回调，Handler 不感知队列。

第一版允许配置更高并发度以支持受控验证，但文档与示例保持 `1`。不在第一版实现工具级优先级、读写锁或取消已排队请求。

## 7. 变更计划生命周期

### 7.1 自动恢复要求

`originalSource` 必须保留到变更完成，因为写入后可能出现语法、解锁、激活或验证失败。不能假设 SAP 历史版本可以等价替代本次预览时的精确源码，也不能把本可自动恢复的异常变成人工恢复。

### 7.2 各状态保留规则

| 状态 | 完整原始/目标源码 | 完整 diff | 保留原因 |
| --- | --- | --- | --- |
| `PREVIEWED` | 保留 | 保留 | 后续漂移校验、确认和应用 |
| `APPLYING` | 保留 | 保留 | 自动回滚 |
| `APPLIED` | 清除 | 清除 | 已验证成功，只需审计摘要 |
| `ROLLED_BACK` | 清除 | 清除 | 已验证恢复成功 |
| `EXPIRED` | 清除 | 清除 | 不可再应用 |
| `FAILED` | 清除 | 清除 | 未写入源码或无需继续自动恢复 |
| `ROLLBACK_FAILED` | 临时保留 | 保留 | 人工恢复需要，最多保留配置时长 |

清理后保留计划编号、系统、客户端、对象元数据、传输号、源码哈希、diff 摘要、语法消息、阶段记录和错误信息。状态查询不得返回完整源码。

### 7.3 淘汰策略

`ChangePlanStore` 在创建、读取、状态变更时惰性清理，不新增定时器：

1. 清除到期的 `PREVIEWED` 内容。
2. 清除超过保留期的 `ROLLBACK_FAILED` 内容。
3. 删除无需继续查询的最旧终态记录，直到低于最大数量。
4. 如果只剩仍有效的 `PREVIEWED/APPLYING/ROLLBACK_FAILED` 且已达到上限，则拒绝创建新计划。

不得为了腾出空间删除仍在应用的计划或尚处人工恢复保留期的回滚失败计划。

## 8. 源码缓存与响应分页

源码缓存继续服务于语法检查和大源码响应分页，但改为受限 LRU：

- Key 为源码 URL，Value 包含源码、写入时间和最近访问时间。
- `get` 时检查 TTL，过期即删除。
- `set` 时按 UTF-8 字节数检查单项限制；超限则不缓存，但原请求正常返回。
- 超过条目上限时删除最久未使用项。
- `logout`、`dropSession` 成功后清空缓存。
- `setObjectSource` 成功后更新缓存。

`getObjectSource` 分页行为：

1. 缓存命中时直接切分缓存源码，不访问 SAP。
2. 缓存未命中时从 SAP 读取完整源码，并在符合限制时缓存。
3. 返回现有分页字段，并增加 `sourceOrigin: "sap" | "cache"`。

这是会话内响应分页，不宣称 SAP 服务端只传输了所需行。

确认挑战继续使用现有 Map，但在计划过期、确认成功、确认取消或计划进入终态时删除；每次访问时惰性删除过期挑战，不增加后台定时器。

## 9. 查询与响应保护

### 9.1 数量参数

第一版只约束已经存在明确数量参数的接口：

- `tableContents.rowNumber`
- `runQuery.rowNumber`
- `searchObject.max`
- 其他发现有等价数量参数的工具复用同一校验函数

规则如下：

- 参数缺失时填充配置默认值。
- 只接受正整数和有限数值。
- 超过服务端上限时在调用 ADT 前拒绝。
- 不静默截断，不自动修改 SQL，不推测用户业务意图。

错误响应说明实际请求值、允许上限，并建议增加过滤条件、减少字段或分批读取。

### 9.2 响应字节上限

Handler 正常返回后、写入 MCP transport 前，对所有文本内容按 UTF-8 计算总字节数。超过 `SAP_MCP_MAX_RESPONSE_BYTES` 时返回结构化超限错误，不把巨型结果继续发送给客户端。

限制发生在 SAP 已返回之后，因此不能替代查询行数上限；它只作为最后一道 Node 内存与 MCP 上下文保护。错误日志不得包含被拒绝的完整响应。

## 10. 日志与审计

### 10.1 普通日志

- `SAP_MCP_LOG_LEVEL` 默认 `warn`，低于配置级别的日志在构造 JSON 前直接跳过。
- 错误日志只包含时间、级别、Handler/工具名、耗时、成功状态、错误类型和关联号。
- 禁止记录凭据、Cookie、Authorization、完整源码、diff、锁句柄或完整工具参数。
- 删除未被调用的 Handler 级 rate limiter 和其 Map；过载由中央执行门控负责。

### 10.2 安全审计

- `AuditLogger` 首次追加时创建目录，后续复用初始化 Promise。
- 使用实例内 Promise 链串行追加 JSONL，避免并发写入行交错。
- 安全变更阶段仍等待对应审计写入成功后继续；不批量缓存、不丢弃、不异步忽略。
- 保留现有字段脱敏和单值长度限制。
- 第一版不自动轮转或删除审计文件，部署文档必须说明由运行环境负责保留、归档和磁盘告警。

## 11. 工具定义与类型质量

- 服务器初始化时构造并缓存 `safeTools`、`legacyTools` 和最终 profile 工具列表，`tools/list` 只返回缓存结果。
- 本次新增代码禁止使用 `any`；错误统一以 `unknown` 接收后安全提取信息。
- 修改到的查询和源码 Handler 为入参定义局部接口并执行运行时边界校验。
- 不在本次引入 ESLint 或全项目格式化，避免将性能治理扩展为无关重构。
- 不修改正常范围内既有工具名称、输入字段和成功响应主体。

## 12. 错误契约

新增错误至少区分：

- 配置错误：启动失败，指出环境变量。
- 队列已满：请求未执行，可稍后重试。
- ADT HTTP 超时：读取可由用户决定是否重试；写入结果未知，必须先核验状态。
- 查询数量超限：请求未执行，提示允许上限。
- 响应字节超限：SAP 请求已完成但响应未发送，提示缩小范围。
- 计划容量已满：新预览未创建，现有计划不受影响。

所有错误保持 MCP `isError: true`，返回稳定的错误代码、阶段、消息和建议动作。内部错误日志与外部安全消息分离。

## 13. 测试与验证

### 13.1 自动测试

保留现有 41 个测试，并新增：

- `ToolExecutionGate` 按 FIFO 串行执行，异常后释放，队列满时拒绝。
- `ADTClient` 收到解析后的底层 timeout 配置。
- 查询默认值、合法上限、负数、小数、非有限值和超限值。
- 响应字节上限按 UTF-8 计算，且错误不包含完整响应。
- 源码缓存命中不调用 SAP、TTL 过期、LRU 淘汰、单项超限不缓存、会话结束清空。
- 计划在 `APPLIED/ROLLED_BACK/EXPIRED/FAILED` 后清除大字段。
- `ROLLBACK_FAILED` 在保留期内保留、到期后清除。
- 最大计划数不会删除有效或正在应用的计划。
- 日志级别在禁用 `info` 时不执行 JSON 序列化和 `stderr.write`。
- 审计并发追加保持完整 JSONL 行和调用顺序。
- 工具定义只构造一次，safe 与 legacy-full profile 内容不变。

Jest 增加 `collectCoverageFrom: ["src/**/*.ts"]` 并排除测试文件。第一阶段只对新增护栏和现有 `safe` 模块设置覆盖率门禁，不要求旧 Handler 一次性达到同一水平。

### 13.2 构建和静态检查

### 13.3 真实 SAP 验证

自动测试与编译不能替代以下运行验证：

- 60 秒默认超时是否适合普通 ADT 请求。
- 调试、ATC、trace 等长任务是否仍使用合适的专用超时。
- 两个同时到达的工具调用是否严格串行，锁与 session 未交叉。
- 5000 行窄表和宽表的实际响应大小与耗时。
- 大源码首次从 SAP 读取、后续分页命中缓存、写入后缓存更新。
- 写入超时、激活失败和回滚失败时的实际 SAP 对象状态。
- 审计目录权限、磁盘容量和日志归档策略。

## 15. 验收标准

- `safe` 与 `legacy-full` 全部工具经过统一参数和响应保护，所有共享 ADTClient 操作经过同一个门控。
- 默认配置下任意两个工具不会同时使用共享 `ADTClient`。
- 查询超限在调用 SAP 前被拒绝，正常范围内仍按用户指定数量执行。
- 已完成或过期计划不再持有完整源码；自动回滚所需状态在应用期间完整保留。
- 源码分页缓存命中时不重复请求 SAP，且缓存有 TTL、容量和单项字节限制。
- 普通成功请求默认不写 info 日志，安全审计不丢失、不交错。
- 现有测试和新增测试全部通过，TypeScript 构建通过。
- 未经真实 SAP 验证前，不宣称超时、吞吐或锁行为已经在运行环境确认。
