# SAP 激活后源码规范化复核设计

> 状态：代码与自动化验证已完成；换行规范化成功路径的真实 SAP DEV 复测仍待执行。当前修改版尚未发布到 npm 或 MCP Registry。

## 1. 背景

`ZCODEX_MCP_TEST` 的真实 SAP DEV 测试已完成锁定、写入、语法检查、解锁和激活，但激活后读取到的源码 SHA-256 与确认计划的目标哈希不同。现有安全流程将其判定为 `VERIFY_FAILED`，随后成功恢复原源码、重新激活、复核原始哈希并解锁，最终状态为 `ROLLED_BACK`。

该结果证明自动回滚有效，但正常写入没有通过。SAP ADT 可能在保存或激活时规范化行结束符或文件末尾换行。当前错误没有记录激活后实际哈希和差异类别，无法直接确认差异是否仅来自换行规范化。

## 2. 目标

- 保留原始 SHA-256，继续提供精确审计证据。
- 允许仅由 `CRLF`、`LF` 和文件末尾换行差异造成的等价源码通过验证。
- 任何非换行字符差异仍视为失败，并执行现有自动回滚。
- 在计划状态、错误详情和审计记录中提供实际源码哈希与匹配类型。
- 不保存额外完整源码，不引入 ABAP 解析器或模糊语义比较。

## 3. 非目标

- 不忽略空格、Tab、注释、大小写或其他文本差异。
- 不改变预览 diff、目标源码、确认绑定哈希或写入内容。
- 不改变锁、传输校验、激活、自动回滚和审计等待语义。
- 不处理查询、缓存、并发门控或响应限制。

## 4. 源码匹配模型

在 `src/safe/sourceTools.ts` 增加一个集中比较函数，返回以下结果：

| 匹配类型 | 条件 | 处理 |
| --- | --- | --- |
| `EXACT` | 原始源码 SHA-256 完全一致 | 验证成功 |
| `LINE_ENDING_NORMALIZED` | 原始哈希不同，但规范化换行后文本完全一致 | 验证成功并记录规范化匹配 |
| `DIFFERENT` | 规范化后仍有任何字符差异 | 验证失败并执行现有回滚 |

规范化只执行两步：

1. 将 `CRLF` 和单独的 `CR` 转换为 `LF`。
2. 移除文件末尾连续的 `LF`，使“无末尾换行”和“一个或多个末尾换行”等价。

不修改字符串中其他位置的空白，也不改变实际提交给 SAP 的源码。

## 5. 工作流变更

### 5.1 激活后验证

读取激活后的 SAP 源码，计算实际原始哈希并与计划目标源码比较：

- `EXACT`：记录 `SOURCE_VERIFIED`，计划进入 `APPLIED`。
- `LINE_ENDING_NORMALIZED`：记录 `SOURCE_VERIFIED`，计划进入 `APPLIED`，同时保留匹配类型和实际哈希。
- `DIFFERENT`：抛出 `VERIFY_FAILED`，错误详情包含目标哈希、实际哈希和匹配类型，随后沿用现有自动回滚。

### 5.2 回滚后验证

恢复原源码并重新激活后使用同一个比较函数：

- `EXACT` 或 `LINE_ENDING_NORMALIZED`：回滚复核成功。
- `DIFFERENT`：保持 `ROLLBACK_FAILED`，要求人工检查。

这避免 SAP 对原源码执行相同换行规范化时产生不必要的恢复失败。

## 6. 状态与审计

计划增加可选诊断字段：

- `verifiedSourceHash`：最近一次成功或失败的写后实际源码哈希。
- `sourceMatchType`：`EXACT`、`LINE_ENDING_NORMALIZED` 或 `DIFFERENT`。
- `rollbackVerifiedSourceHash`：回滚后实际源码哈希。
- `rollbackSourceMatchType`：回滚后的匹配类型。

字段进入 `ChangePlanView` 和审计 JSONL，但不记录实际完整源码、Cookie、锁句柄或凭据。终态清理继续移除计划中的完整源码和 diff，不清除这些小型诊断字段。

## 7. 错误处理

- `DIFFERENT` 的外部错误仍使用 `VERIFY_FAILED`，保持现有调用方契约。
- 错误详情增加哈希和匹配类型，不加入完整源码或完整 diff。
- 自动回滚路径和单次消费规则保持不变。
- 写入超时仍视为远端结果未知，不自动重试。

## 8. 测试与验收

### 8.1 自动测试

- 完全相同源码返回 `EXACT`。
- `CRLF`、`LF`、单独 `CR` 和文件末尾换行差异返回 `LINE_ENDING_NORMALIZED`。
- 空格、注释或任意非换行字符差异返回 `DIFFERENT`。
- 激活后仅换行规范化时计划进入 `APPLIED`，不调用回滚写入。
- 激活后真实内容差异时仍进入自动回滚。
- 回滚后仅换行规范化时可进入 `ROLLED_BACK`。
- 计划状态、错误详情和审计包含诊断字段，不包含完整源码。
- 全量 Jest、TypeScript 构建和 `git diff --check` 通过。

### 8.2 真实 SAP DEV

使用 `PROGRAM ZCODEX_MCP_TEST` 和未释放请求 `S4HK900009`：

1. 重新读取当前源码并确认仍为原哈希。
2. 预览仅增加一行测试注释的完整源码。
3. 经用户确认后执行应用。
4. 验收最终状态为 `APPLIED`，测试注释真实存在，激活后源码匹配类型为 `EXACT` 或 `LINE_ENDING_NORMALIZED`。
5. 验证无残留锁、审计链完整且实际哈希已记录。
6. 测试完成后，另行经过预览和用户确认恢复原源码。

## 9. 安全边界

本设计只放宽换行表示差异，不放宽源码内容差异。任何非换行字符变化继续触发原有自动回滚，因此不会把 SAP 未按确认内容保存的结果误判为成功。
