# 函数组 Typed Activation 修复设计

## 1. 背景与目标

安全对象创建流程已经能够成功创建并验证 `PROGRAM`。在 SAP DEV 客户端 `300`、开发包 `Z001`、传输请求 `S4HK900011` 上创建 `FUNCTION_GROUP ZMCP_IF_TEST` 时，ADT 创建请求成功，但随后的激活返回失败且没有错误短消息。工作流按既定安全规则删除了本次计划能证明归属的函数组，最终状态为 `COMPENSATED`；子函数模块尚未创建。

本次修复的目标是让新建函数组使用包含对象类型和父包 URI 的 ADT typed activation 请求，同时保持现有确认、验证、补偿和审计边界不变。

## 2. 根因判断

当前创建工作流的激活方式按对象类型分为两类：

- `FUNCTION_MODULE` 使用 typed activation，发送对象 URI、`FUGR/FF`、对象名和父函数组 URI。
- `PROGRAM` 与 `FUNCTION_GROUP` 使用字符串重载，只发送对象名和对象 URI。

`abap-adt-api` 的字符串重载不会在激活 XML 中发送 `adtcore:type` 和 `adtcore:parentUri`。结合本次函数组创建成功、激活返回 `success=false` 且没有短错误消息的现场结果，最可信的根因是目标 SAP 系统要求函数组使用完整对象引用，而当前请求缺少类型和父包 URI。该判断需要通过修复后的真实 SAP DEV 复测最终确认。

现有自动化测试只验证函数组路径调用了 `activate`，没有断言调用重载、对象类型和父包 URI，因而没有发现此差异。

## 3. 修复范围

### 3.1 包含

- 新建 `FUNCTION_GROUP` 使用 typed activation。
- typed object reference 使用创建计划已经冻结并在应用前复核的字段：
  - `adtcore:uri`：创建后解析得到的实际函数组 URI。
  - `adtcore:type`：`FUGR/F`。
  - `adtcore:name`：函数组名称。
  - `adtcore:parentUri`：开发包 URI，例如 `/sap/bc/adt/packages/z001`。
- 函数组激活失败时，在不泄露源码、凭据、Cookie、锁句柄或完整 SAP 响应的前提下，记录 inactive 对象数量和与当前对象匹配的安全元数据。
- 增加精确测试，验证函数组和函数模块均使用正确的 typed activation 参数。
- 更新中文使用指南中的真实 SAP DEV 验证状态。

### 3.2 不包含

- 不改变 `PROGRAM` 的现有字符串激活方式。
- 不改变函数模块接口参数维护能力；该能力仍属于后续第二阶段。
- 不改为函数组和函数模块批量激活。
- 不跳过函数组激活。
- 不修改传输请求，不创建或释放传输。
- 不自动重试任何结果不确定的 SAP 写请求。
- 不清理已成功创建的 `PROGRAM ZMCP_CREATE_TEST`。

## 4. 处理流程

修复后的“新函数组 + 首个函数模块”流程保持顺序执行：

1. 应用前重新验证系统策略、传输、包、父子关系和目标不存在。
2. 创建函数组。
3. 解析非活动版本，证明实际对象 URI 与计划目标一致。
4. 使用 `FUGR/F`、实际 URI、对象名和父包 URI 执行 typed activation。
5. 按活动版本重新解析函数组，证明激活成功。
6. 在新函数组下验证并创建函数模块。
7. 写入完整函数模块源码，执行语法检查、解锁和 typed activation。
8. 复读活动源码并仅容忍换行规范化。

如果第 4 步或后续步骤失败，仍只删除本计划能够证明归属的对象，并按函数模块、函数组的反向依赖顺序补偿。

## 5. 激活失败诊断

当 `activate` 返回 `success=false` 时，错误仍归类为 `ACTIVATION_FAILED / activate`。错误详情只允许包含：

- 当前对象类型和名称。
- `inactiveCount`。
- inactive 结果中匹配当前对象的 URI、类型、名称和父 URI。
- SAP 返回的短消息文本；为空时使用稳定的中文可理解错误摘要。

不得记录或返回完整激活响应、源码、传输任务内容、用户标识、Cookie、CSRF Token 或锁句柄。

如果激活请求抛出网络超时或连接错误，结果视为不确定。工作流不得假设激活失败并盲目删除；必须先只读检查目标对象和 inactive/active 状态，再决定是否允许补偿。这一未知结果保护沿用创建工作流现有原则，不因本次修复放宽。

## 6. 自动化验证

新增或调整测试必须覆盖：

- 函数组激活调用 typed overload。
- 函数组对象引用精确包含 `FUGR/F` 和父包 URI。
- 函数模块仍包含 `FUGR/FF` 和父函数组 URI。
- 程序激活调用方式保持不变。
- typed activation 返回 inactive 对象时，计划进入安全补偿流程。
- 错误详情包含安全诊断，不包含源码、锁句柄或凭据。
- 函数组激活成功后才验证并创建子函数模块。
- 补偿仍按函数模块、函数组的反向顺序执行。

执行完整 Jest、TypeScript 构建和 `git diff --check`。由于工作区同时存在未提交的 SM21 功能，必须分别验证本次提交快照和完整工作区，并精确暂存，不得把 SM21 内容带入本次修复提交。
