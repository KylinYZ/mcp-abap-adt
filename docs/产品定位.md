# ABAP ADT MCP 的产品定位

## 一句话

这是一个面向 SAP 团队的 **AI 原生 ABAP 工作台**：让开发人员可以读、改、检查和调试 ABAP，让业务顾问可以查询业务数据和定义，让运维人员可以查看运行现场与传输状态。

它不是一套把用户挡在 ADT 细节之外的审批系统。安全策略是可配置的执行边界，产品本身应该首先让熟悉 SAP 的人高效完成工作。

## 使用者优先级

| 优先级 | 角色 | 主要任务 | 默认入口 |
| --- | --- | --- | --- |
| 1 | 开发人员 | 源码阅读/修改、对象创建、语法检查、单测、ATC、调试、依赖分析 | `focused`（别名：`developer`） |
| 2 | 业务顾问 | 表结构、业务数据、字典定义、对象搜索和结果解释 | `business` |
| 3 | 运维人员 | Dump、SM21、Trace、传输、版本和已有调试现场 | `operations` |

`expert` 适合需要完整低层 ADT 工具面的专家和旧脚本。`safe`、`development` 等名称保留用于兼容已有部署，不再作为新用户的认知入口。

## 设计原则

1. **按工作任务组织能力**：用户先选择开发、业务或运维，不必先理解七套内部 profile。
2. **Focused 优先**：默认只展示一组可完成日常工作的工具，工具描述负责告诉模型下一步，不把内部状态机暴露成主要产品概念。
3. **SAP 权限是最终边界**：MCP 不替代 SAP 角色、client、传输和审计治理；在 DEV、QAS、PRD 使用相同入口时，由系统角色决定可执行范围。
4. **风险随操作上升**：读操作直接完成；写入、调试控制和发布等动作仍遵循当前部署配置的确认与复查策略，但错误应解释“怎么继续”，而不是只返回一串内部门禁名。
5. **兼容而不绑架体验**：旧 profile 和低层工具继续支持迁移与脚本场景，新文档和示例只推荐角色入口。

## 能力分层

- **Focused（开发）**：源码、对象、搜索、数据预览、测试、调试、质量检查和常用传输信息。
- **Business（业务）**：schema-first 的定义和有界数据读取，不包含写入和调试控制。
- **Operations（运维）**：运行日志、Dump、Trace、传输和现场调试读取，不包含业务数据修改。
- **Expert（专家兼容）**：完整低层 ADT 面；仅在用户明确需要原子 ADT 操作或旧脚本兼容时启用。

## 与 vibing-steampunk 的关系

本项目借鉴 `vibing-steampunk` 的 Focused/Expert 思路：默认给 AI 一组足够完成工作的能力，专家再显式展开全部原子工具。两者的 ADT 覆盖和实现语言不同；本项目继续复用现有 TypeScript ADT 客户端、SAP 角色判断和部署配置，不把另一项目的命令或协议直接移植过来。

## 配置速查

```dotenv
# 新安装推荐
SAP_MCP_TOOL_PROFILE=focused

# 角色入口
# focused/developer -> development-workbench
# business          -> business-readonly
# operations        -> operations-readonly
# expert            -> legacy-full
```

如果需要最小化开发工具集，可继续使用 `safe`；如果需要旧版本的宽兼容面，可使用 `development` 或 `legacy-full`。这些是部署兼容选项，不是产品定位。
