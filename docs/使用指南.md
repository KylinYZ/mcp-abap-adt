# mcp-abap-abap-adt-api 使用指南

## 1. 当前分发状态

截至 2026-08-18，`0.4.0` 已以 `@kylinyz/mcp-abap-abap-adt-api` 发布到 npm。MCP Registry 与 Marketplace 是否收录仍需在对应客户端单独核验。

常规使用推荐固定 npm 版本：`npx -y @kylinyz/mcp-abap-abap-adt-api@0.4.0`。开发、验证本地修改或无法访问 npm 时，仍可在本分支源码目录安装依赖、构建 `dist`，再让 Codex、Claude 或其他 MCP 客户端通过 `node` 启动 `dist/index.js` 的绝对路径。不能假定重新克隆上游仓库会包含本文描述的分支修改。

`package.json` 和 `server.json` 中的 npm 元数据对应已发布的 `0.4.0`；Registry/Marketplace 状态与 npm 发布状态分开判断。

完整 ADT 客户端已内置在 `src/adt/`，安装和运行不依赖外部 `abap-adt-api` npm 包。内置源码基于上游 `abap-adt-api` 8.4.2 和 MIT License；版本提交 `43f6dc7`、迁入提交 `3cd8c17`、本地取消语义及更新步骤记录在 [`third-party/abap-adt-api/BASELINE.md`](../third-party/abap-adt-api/BASELINE.md)，许可证原文保存在同目录 `LICENSE`。

## 2. 使用前准备

需要满足：

- Windows 上已安装 Node.js 18 或更高版本和 npm。
- SAP ABAP 开发系统可通过 ADT 访问。
- `SICF` 中已启用 `/sap/bc/adt`。
- SAP 用户具备目标对象、语法检查、锁定、激活和传输请求所需权限。
- 安全修改对象属于允许的 `Z`/`Y` 命名空间，并位于可传输包中，不能是 `$TMP`。
- 使用一个已有、未释放且 SAP 报告为目标对象可用的十位传输请求。

如选择源码构建方式，在项目目录执行：

```powershell
node -v
npm -v
npm install
Copy-Item .env.example .env
npm run build
```

项目当前路径示例：

```text
D:\MyDev\SAP\mcp-abap-abap-adt-api
```

## 3. 配置 `.env`

不要把 `.env` 提交到 Git，也不要在聊天、日志或截图中公开密码。

单实例可继续使用程序旁的 `.env`。多实例必须在每个 MCP 进程环境中设置不同的绝对 `SAP_MCP_ENV_FILE`；该变量用于选择 dotenv 文件，必须在进程启动前提供，不能写在被选择的文件内部。显式文件不存在或不可读时服务拒绝启动。

连接服务的三个启动必需项是 `SAP_URL`、`SAP_USER`、`SAP_PASSWORD`。`SAP_CLIENT` 和 `SAP_LANGUAGE` 会传给 ADT 客户端；安全工具还要求客户端号参与白名单校验，因此实际使用 `safe` 时应明确填写。

推荐的最小安全配置：

```env
SAP_URL=https://your-sap-server.com:44300
SAP_USER=YOUR_SAP_USERNAME
SAP_PASSWORD=YOUR_SAP_PASSWORD
SAP_CLIENT=100
SAP_LANGUAGE=ZH

SAP_MCP_TOOL_PROFILE=safe
SAP_MCP_SYSTEM_ROLE=DEV
SAP_MCP_ALLOWED_HOSTS=your-sap-server.com
SAP_MCP_ALLOWED_CLIENTS=100
SAP_MCP_ALLOWED_NAMESPACES=Z,Y
SAP_MCP_CHANGE_PLAN_TTL_SECONDS=900
SAP_MCP_ALLOWED_DEBUG_USERS=
SAP_MCP_DEBUG_AUTH_TTL_SECONDS=900
SAP_MCP_AUDIT_PATH=D:\sap-mcp-audit
SAP_MCP_ALLOW_TEXT_CONFIRMATION=false
```

说明：

- `SAP_MCP_TOOL_PROFILE=safe`：默认只开放七个高层受控工具，包括源码修改和对象创建。
- `SAP_MCP_SYSTEM_ROLE=DEV`：只有显式 DEV 角色可以执行写入与调试控制。QAS、PRD、缺失角色或非法角色无论选择哪个 Profile，都只允许本地和只读操作。
- `SAP_MCP_ALLOWED_HOSTS`：填写 `SAP_URL` 中的主机名，不含协议和端口。
- `SAP_MCP_ALLOWED_CLIENTS`：三位客户端号，可以用逗号配置多个。
- `SAP_MCP_ALLOWED_NAMESPACES`：允许的对象名前缀，默认建议仅 `Z,Y`。
- `SAP_MCP_CHANGE_PLAN_TTL_SECONDS`：计划有效期，范围 60–3600 秒，当前建议 900 秒。
- `SAP_MCP_ALLOWED_DEBUG_USERS`：DEV 调试控制用户白名单，支持逗号分隔多个 SAP 用户；未配置时仅允许当前 `SAP_USER`。
- `SAP_MCP_DEBUG_AUTH_TTL_SECONDS`：调试会话授权有效期，范围 60–3600 秒，默认 900 秒。
- `SAP_MCP_AUDIT_PATH`：MCP 进程必须有写权限；安全修改在审计不可写时关闭失败。
- `SAP_MCP_ALLOW_TEXT_CONFIRMATION=false`：优先使用原生 MCP 弹框。只有客户端不支持 form elicitation 时，才考虑显式启用文字降级。

`safe` 模式的源码读取要求角色、主机、客户端和命名空间全部匹配；源码修改和对象创建还要求可写审计目录、可传输包和已有未释放传输请求。DEV `legacy-full` 的低层工具不会套用受控 preview/apply 工作流，但仍受角色策略以及第 5 节的参数大小、响应大小、超时、查询/搜索数量和执行队列护栏保护。Profile 只决定候选工具集合，系统角色会再次过滤目录并在 dispatch 前拦截隐藏工具直调。

如果开发系统使用自签名证书，可在受控开发环境增加：

```env
NODE_TLS_REJECT_UNAUTHORIZED=0
```

这会关闭 Node.js TLS 证书校验，不建议在生产或不受控网络使用。

## 4. MCP 功能与工具清单

### 4.1 Profile 总览

| Profile | 工具数 | 组成 | 安全边界 |
| --- | ---: | --- | --- |
| `safe`（默认） | 7 | 七个高层源码变更与对象创建工具 | 全部经过 DEV/主机/客户端/命名空间/传输/审计策略；写入必须预览并由服务器取得一次确认 |
| `development` | 118 | 向后兼容的宽开发与诊断工具面；仅 DEV 保持完整集合 |
| `diagnostic-readonly` | 98 | 向后兼容的宽只读诊断工具面；DEV/QAS/PRD 全部只读 |
| `legacy-full` | 161 | 7 个安全工具 + 6 个高层运行工具 + 148 个原始低层 ADT 工具 | 完整数量仅指 DEV；原始写入/删除不经过安全预览与确认流程 |
| `development-workbench` | 81 | 聚焦开发、安全调试、受控高级操作和质量检查 | 供开发 Skill 使用 |
| `business-readonly` | 17 | schema 优先、有界业务数据读取 | 供业务数据 Skill 在 DEV/QAS/PRD 使用 |
| `operations-readonly` | 40 | 运行、版本、trace 与已有调试现场读取 | 供运维 Skill 在 DEV/QAS/PRD 使用 |

正式 Skill 不依赖 `legacy-full`。由于 profile 在进程启动时固定，Workbench 使用三个 SAP 环境、七个 MCP 别名；模型不能通过工具参数临时切换 profile、系统、客户端或进程。

推荐的七别名策略：

| 实例名 | `SAP_MCP_TOOL_PROFILE` | `SAP_MCP_SYSTEM_ROLE` | 能力边界 |
| --- | --- | --- | --- |
| `sap-dev` | `development-workbench` | `DEV` | 开发、质量检查、安全源码、受控高级操作和安全调试 |
| `sap-dev-business` / `sap-qas-business` / `sap-prd-business` | `business-readonly` | 对应 `DEV` / `QAS` / `PRD` | 只读业务数据与 schema |
| `sap-dev-ops` / `sap-qas-ops` / `sap-prd-ops` | `operations-readonly` | 对应 `DEV` / `QAS` / `PRD` | 只读运行、版本、trace 与已有调试现场 |

七个别名必须通过各自进程环境中的 `SAP_MCP_ENV_FILE` 选择固定配置文件；同一 SAP 环境可复用连接值，但 profile 和审计路径应按进程明确配置。仅改变启动目录不会切换默认的程序旁 `.env`。Profile 不是工具参数，模型不能在一次调用中切换 host、client 或系统角色。

### 4.2 默认 `safe` 的七个工具

| 工具 | 类型 | 功能 |
| --- | --- | --- |
| `inspectAbapObject` | 只读 SAP | 默认读取白名单内 `PROGRAM`、`INCLUDE`、`CLASS` 或 `FUNCTION_MODULE` 的完整源码、元数据与哈希；大型源码支持 `startLine`/`maxLines` 分页。 |
| `previewAbapChange` | 只读 SAP | 校验对象、传输、完整目标源码和语法，返回完整 Markdown diff 与短时计划；不锁定、不写入、不激活。 |
| `applyAbapChange` | 确认后写 SAP | 应用已预览计划，执行源码漂移检查、锁定、写入、语法检查、解锁、激活、复读验证和失败恢复。 |
| `getAbapChangeStatus` | 仅本地 | 查询变更计划、阶段、验证、解锁和回滚状态，不返回完整源码。 |
| `previewAbapObjectCreation` | 只读 SAP | 校验并冻结 `PROGRAM`、`FUNCTION_GROUP`、`FUNCTION_MODULE` 创建计划；不创建对象。 |
| `applyAbapObjectCreation` | 确认后写 SAP | 按依赖顺序创建、写源码、检查、解锁、激活和复读；失败时执行有归属证明的反向补偿。 |
| `getAbapObjectCreationStatus` | 仅本地 | 查询创建对象、归属证明、激活和补偿状态，不返回完整源码。 |

### 4.3 `development` 的八个安全调试工具

| 工具 | 确认与作用 |
| --- | --- |
| `previewDebugOperation` | 冻结创建/删除监听器、设置/删除断点、Attach、保存设置、跳转行或终止进程计划；不直接执行控制动作。 |
| `applyDebugOperation` | 对冻结计划打开原生 form 弹框；监听器、断点、Attach、设置每计划确认一次，跳转行和终止进程每次单独确认。 |
| `getDebugOperationStatus` | 只读本地计划状态、哈希、脱敏摘要和未知结果信息。 |
| `authorizeDebugSession` | 对当前安全 Attach 上下文进行一次原生确认，默认授权 15 分钟。 |
| `executeDebugCommand` | 有效授权内每次只执行一个 Step、Continue、运行到行或栈导航命令，然后立即复读调用栈。 |
| `previewDebugVariableChange` | 读取并冻结当前栈帧、变量原值和目标值；外部视图只返回哈希和字节摘要。 |
| `applyDebugVariableChange` | 每次单独原生确认；应用前复读栈帧和原值，任何漂移都会拒绝修改。 |
| `revokeDebugSession` | 撤销进程内授权，不修改 SAP。 |

安全调试只支持 MCP `elicitation.form`，即使 `SAP_MCP_ALLOW_TEXT_CONFIRMATION=true` 也不会降级为文字确认。授权绑定 host、client、SAP 用户、debuggee、debug session、进程和服务器；重新 Attach、debuggee 变化、终止、超时、MCP 重启或显式撤销后失效。每次调用只接受一个命令，不支持命令数组、自动循环 Step 或自动重放 Continue。

远端控制调用发生超时或连接异常时，计划标记为 `UNKNOWN` 或返回 `remote_result_unknown`。服务只尝试读取监听器或调用栈等状态，不会重复刚才的控制动作。审计只记录操作、用户、debuggee、计划/授权哈希、变量值哈希和脱敏结果，不记录变量完整值。

### 4.4 三个诊断 Profile 共用的运行日志工具

| 工具 | 功能 | 前置条件 |
| --- | --- | --- |
| `sm21Read` | 通过复用当前 ADT HTTP 会话，按时间、实例、用户、程序、事务码、消息 ID、严重级别和分页条件只读查询 SM21 系统日志。 | 部署并激活 `sap/adt-http/ZCL_MCP_SM21_ADT_HTTP.abap`，配置 SICF，ADT 用户具有 `S_ADMI_FCD=SM21`。 |
| `analyzeRuntimeErrors` | 同时读取 SM21 和 ADT ST22 dump 摘要，只按文本证据给出保守关联；不会把单一匹配声明为确定因果。 | 与 `sm21Read` 相同，并要求当前用户能读取 ADT dump feed。 |

SM21 工具不接收用户名、密码或 RFC destination；无需 `node-rfc`、SAP NW RFC SDK、JCo 或 NCo。SAP 端部署步骤见 [`sap/adt-http/ZCL_MCP_SM21_ADT_HTTP-deployment.md`](../sap/adt-http/ZCL_MCP_SM21_ADT_HTTP-deployment.md)。如果未部署该服务，工具仍会出现在 `legacy-full` 列表中，但调用会失败。

推荐使用包含时区偏移的 ISO 8601 入参，例如 `2026-08-13T08:00:00+08:00`；服务先解析为绝对时间，再按 `SAP_MCP_SM21_TIMEZONE` 转换为 SAP 日志时间戳。时间窗口不能超过配置上限，五类过滤数组各最多 20 项、每项最多 80 个字符，`severity` 只接受 `ALL`、`ERROR`、`WARNING`、`ERROR_WARNING`。

### 4.5 只读 Profile 的工具边界

宽兼容 Profile `development` 和 `diagnostic-readonly` 只选择经过审核的低层读取工具，并保留高层读取和运行日志工具。正式 Workbench 使用更窄的三个任务型 Profile。它们不开放 `setObjectSource`、`createObject`、`deleteObject`、传输释放、原始低层调试控制、Trace 配置变更、Git 推送、原始服务发布、重命名执行、重构执行和其他低层写入路径。只有 DEV `development-workbench` 注册质量检查工具，并包含八个高层安全调试门面和六个受控高级 preview/apply 工具。

只读 Profile 的访问仍必须满足系统角色、主机、客户端和适用白名单；它们不注册源码修改或调试控制工具。即使 QAS/PRD 被错误配置为开发或 `legacy-full`，服务端也只列出本地/只读工具，并在访问 ADT 前拒绝写入与调试控制。缺失或非法角色同样关闭失败为只读。

### 4.7 `development` 的六个受控高级工具

| 工具 | 远端副作用 | 作用 |
| --- | --- | --- |
| `previewDdicPropertyChange` | 无写入 | 读取当前 domain、data element 或文本元素，校验 transport，返回有界差异和 `operationPlanId`。 |
| `applyDdicPropertyChange` | 确认后写入 | 只接受服务器计划 ID；原生确认后重新检查漂移，最多写入一次并复读验证。仅在结果明确时尝试一次受控恢复。 |
| `previewPackageChange` | 无写入 | 调用包迁移 preview，冻结目标、旧包、新包、transport 和影响对象摘要。 |
| `applyPackageChange` | 确认后迁移 | 漂移复查后最多 execute 一次；不自动反向迁移。 |
| `previewRapOperation` | 无生成/发布 | 校验并预览 `RAP_GENERATE` 或 `RAP_PUBLISH_SERVICE`，返回对象/状态摘要和计划。 |
| `applyRapOperation` | 确认后生成或发布 | 最多 generate/publish 一次，再只读复查；不自动删除生成对象、取消发布或重试。 |

统一流程是：preview -> 向用户展示结果 -> 使用 `operationPlanId` 调用对应 apply -> MCP 打开唯一一次原生 form 确认 -> 服务端复查策略与漂移 -> 最多执行一次 -> 只读核验。高级 apply 不支持文字确认降级。`UNKNOWN_OUTCOME` 表示网络或响应状态不足以证明成功或失败；必须停止自动化写入，先用只读工具核对对象、包或发布状态，再由用户决定是否建立新计划。

## 5. 性能与资源配置

`.env.example` 已提供推荐默认值：

| 环境变量 | 默认值 | 范围 | 作用 |
| --- | ---: | --- | --- |

## 9. 安全修改操作

### 第一步：读取当前源码

调用：

```text
inspectAbapObject
```

参数：

```json
{
  "objectType": "PROGRAM",
  "objectName": "ZYOUR_TEST_PROGRAM"
}
```

支持的 `objectType`：

- `PROGRAM`
- `INCLUDE`
- `CLASS`
- `FUNCTION_MODULE`

大型源码建议每页 300 行：

```json
{
  "objectType": "PROGRAM",
  "objectName": "ZYOUR_TEST_PROGRAM",
  "startLine": 1,
  "maxLines": 300
}
```

下一页使用 `startLine + returnedLines`。只有所有页面的完整 `sourceHash` 相同、行范围连续、累计行数等于 `totalLines`，并且末页 `hasMore=false` 时，才能把分页结果视为完整源码；哈希变化时丢弃已有页面并从第一页重新读取。

必须以返回的完整源码作为后续编辑基线，不要只提交局部片段。

### 第二步：预览完整修改

调用：

```text
previewAbapChange
```

参数：

```json
{
  "objectType": "PROGRAM",
  "objectName": "ZYOUR_TEST_PROGRAM",
  "newSource": "完整的目标 ABAP 源码",
  "transportRequest": "DEVK900001"
}
```

预览阶段会：

1. 校验 DEV、主机、客户端和命名空间策略。
2. 精确解析目标 ADT 对象。
3. 确认对象不在 `$TMP`。
4. 确认传输请求是十位且 SAP 报告为对象可用、未释放。
5. 读取当前源码并生成原始哈希。
6. 检查完整目标源码语法。
7. 在工具内容中返回可直接展示的完整 Markdown diff，同时返回机器可读的短时 `changePlanId` 和计划数据。

预览不会锁定、写入或激活 SAP 对象。

### 第三步：审阅 diff

人工确认至少包括：

- 对象类型和对象名正确。
- 传输请求正确。
- diff 只包含预期修改。
- 没有删除必要声明、Include 或方法实现。
- 没有凭据、测试后门或无边界数据访问。

如果 diff 不正确，不要应用；修改完整目标源码后重新预览。

diff 审阅完成后，客户端应直接调用 `applyAbapChange` 打开服务器确认选项，不要再要求用户先在聊天中输入“确认应用”。

### 第四步：应用计划

调用：

```text
applyAbapChange
```

参数：

```json
{
  "changePlanId": "preview 返回的计划编号"
}
```

支持原生 form elicitation 的客户端会显示唯一一次确认：

- `应用变更`
- `取消`

选择取消、点击跳过、关闭弹框、未选择或等待超时都不会写入 SAP。超时后计划仍保持 `PREVIEWED`；计划有效期内可再次调用应用重新弹框。

确认应用后，服务按顺序执行：

1. 再次验证传输请求。
2. 复读 SAP 源码并检查是否发生漂移。
3. 获取 `MODIFY` 锁。
4. 写入计划绑定的完整目标源码。
5. 再次执行语法检查。
6. 解锁。
7. 激活对象。
8. 复读激活后的源码并校验。

源码验证允许 SAP 仅规范化 `CRLF`、`LF`、单独 `CR` 和文件末尾换行；这种情况记录为 `LINE_ENDING_NORMALIZED`。对于完整函数模块源码，还允许 SAP 改变签名终止句点与首条正文之间的连续空行数量，并记录为 `FUNCTION_MODULE_FORMAT_NORMALIZED`。参数、正文、注释、缩进、正文内部空行或其他字符差异仍为 `DIFFERENT`，并触发失败恢复。

### 第五步：检查结果

成功结果应满足：

- 计划状态为 `APPLIED`。
- `SOURCE_VERIFIED` 阶段成功。
- `sourceMatchType` 为 `EXACT`、`LINE_ENDING_NORMALIZED` 或函数模块专用的 `FUNCTION_MODULE_FORMAT_NORMALIZED`。
- `unlockSucceeded=true`。

需要详细阶段时调用：

```json
{
  "changePlanId": "计划编号"
}
```

对应工具为 `getAbapChangeStatus`。

## 10. 安全创建对象

对象创建仍采用“预览计划 → 用户确认 → 应用计划 → 查询状态”，不能直接把 `confirmedByUser` 作为参数传入。

首期支持以下对象图：

- 单个 `PROGRAM`。
- 单个 `FUNCTION_MODULE`，父函数组必须已经存在。
- 一个新 `FUNCTION_GROUP`，紧接其首个 `FUNCTION_MODULE`。

单独空 `FUNCTION_GROUP` 暂时拒绝：目标系统只有组合创建的 Eclipse 抓包证据，尚未确认 standalone 函数组的可靠激活请求。函数组源码及 `L<函数组>TOP`、`L<函数组>UXX` 等 Include 由 SAP 生成，调用方不能提交函数组源码，也不能创建或释放传输请求。

函数模块的导入、导出、更改、表和异常参数写在完整 `source/main` 的 `FUNCTION ... .` 签名中，与实现代码一起进入预览、确认、源码哈希、写入和复读验证。当前没有结构化参数数组生成器，必须提交完整 ABAP 源码。

### 第一步：预览创建

调用 `previewAbapObjectCreation`。以下示例是带注释的 JSONC，不是严格 JSON。

创建程序：

```jsonc
{
  "objects": [{
    "objectType": "PROGRAM",
    "objectName": "ZYOUR_NEW_PROGRAM",
    "description": "受控创建测试程序",
    "packageName": "ZYOUR_PACKAGE",
    // 必须提交完整源码，且名称与 objectName 一致。
    "source": "REPORT zyour_new_program.\nWRITE / 'Created by safe workflow'."
  }],
  "transportRequest": "DEVK900001"
}
```

在已有函数组中创建函数模块：

```jsonc
{
  "objects": [{
    "objectType": "FUNCTION_MODULE",
    "objectName": "ZYOUR_NEW_FM",
    "description": "受控创建测试函数",
    "parentFunctionGroup": "ZYOUR_EXISTING_FG",
    // 不接受 packageName；包由父函数组确定。参数签名属于完整源码。
    "source": "FUNCTION zyour_new_fm\n  IMPORTING\n    VALUE(iv_input) TYPE string\n  EXPORTING\n    VALUE(ev_output) TYPE string.\n\n  ev_output = iv_input.\nENDFUNCTION."
  }],
  "transportRequest": "DEVK900001"
}
```

创建新函数组及首个函数模块：

```jsonc
{
  "objects": [
    {
      "objectType": "FUNCTION_GROUP",
      "objectName": "ZYOUR_NEW_FG",
      "description": "受控创建测试函数组",
      "packageName": "ZYOUR_PACKAGE"
      // 不允许 source，函数池和标准 Include 由 SAP 生成。
    },
    {
      "objectType": "FUNCTION_MODULE",
      "objectName": "ZYOUR_NEW_FM",
      "description": "新函数组的首个函数模块",
      "parentFunctionGroup": "ZYOUR_NEW_FG",
      "source": "FUNCTION zyour_new_fm\n  IMPORTING\n    VALUE(iv_input) TYPE string\n  EXPORTING\n    VALUE(ev_output) TYPE string.\n\n  ev_output = iv_input.\nENDFUNCTION."
    }
  ],
  "transportRequest": "DEVK900001"
}
```

预览会验证策略、对象图、父对象、目标不存在、包和传输，并调用可执行的 ADT 名称校验。新函数组尚不存在时，其子函数模块的 ADT 名称校验会明确延迟到应用阶段、父函数组创建成功之后。预创建语法检查也会延迟，因为目标源码 URL 尚不存在。

### 第二步：确认并应用

调用 `applyAbapObjectCreation`：

```json
{
  "creationPlanId": "预览返回的计划编号"
}
```

原生确认弹框会列出对象图和传输请求。客户端不支持弹框且显式启用了文字降级时，第一次调用会返回一次性中文确认短语，第二次必须原样提交。

应用会重新验证策略、传输和目标不存在，再按依赖顺序创建。程序和函数模块会执行锁定、整段源码写入、语法检查、解锁、激活和复读。组合创建时，函数组创建后保持 inactive，不单独发送激活请求；首个函数模块按 Eclipse 的 `name + URI` 请求激活后，再分别复核函数模块和父函数组的 active 版本。函数池源码始终由 SAP 管理。

创建不是数据库事务。失败时服务按反向依赖顺序删除当前计划已经证明归属的对象；若创建请求结果不确定、对象身份无法证明或删除失败，服务停止自动恢复并将计划置为 `COMPENSATION_FAILED`，必须人工检查 SAP 对象、锁和传输，禁止盲目重试。

### 第三步：查询状态

调用 `getAbapObjectCreationStatus`：

```json
{
  "creationPlanId": "创建计划编号"
}
```

成功状态为 `APPLIED`。失败后重点检查 `createdObjects`、`ownershipProven`、`compensationAttempted` 和 `compensationSucceeded`。

### 当前验证边界

截至 2026-08-13，创建 resolver、计划存储、确认机制、工具接线、程序创建流程、新函数组加首个函数模块的依赖顺序，以及反向补偿已通过自动化测试和 TypeScript 构建。

真实 SAP DEV 已验证 `PROGRAM ZMCP_CREATE_TEST` 在客户端 `300`、开发包 `Z001`、传输 `S4HK900011` 中创建、写入、语法检查、解锁、激活和复读成功；SAP 只做了允许的换行规范化，对象按确认保留。第一次创建 `FUNCTION_GROUP ZMCP_IF_TEST` 时，旧实现的字符串激活返回失败，安全流程随后删除补偿成功并进入 `COMPENSATED`；`FUNCTION_MODULE Z_MCP_IF_TEST` 尚未创建，只读复查确认两个函数对象均无残留。

Eclipse ADT 3.60.2 随后使用 `ZMCP_ADT_TRACE + Z_MCP_ADT_TRACE` 完成了组合创建和参数源码写入。Communication Log 证明组合流程没有独立函数组激活；源码 `PUT .../source/main` 直接包含 `IMPORTING/EXPORTING`；激活 XML 只包含函数模块 `uri + name`，并使用 `preauditRequested=true`。旧 typed activation 推测已被该现场证伪，MCP 已按真实请求形态完成代码和定向测试修正。

修正协议后的首次 MCP 真实复测中，`ZMCP_IF_TEST + Z_MCP_IF_TEST` 已完成创建、完整源码写入、语法检查、解锁和激活。SAP active 源码只把换行改为 CRLF，并将函数签名后的分隔区补为三个空行；旧比较器因此误判 `DIFFERENT`，安全流程随后按函数模块到函数组的顺序补偿成功，计划终态为 `COMPENSATED`，两次只读搜索确认对象无残留。现已增加只允许该签名分隔区变化的 `FUNCTION_MODULE_FORMAT_NORMALIZED`，参数、实现、注释和其他空白仍严格比较；该修复尚待重启后完成最终真实成功复测。

激活请求抛出超时或连接异常时，流程仍先只读核对 active/inactive 版本；无法确认远端结果时禁止自动删除并要求人工检查。修正后的组合创建尚未重新执行真实 SAP DEV 写入，必须在重启 MCP、重新预览并再次取得明确确认后，使用新对象复测。

## 11. DEV 受控 DDIC、开发包与 RAP 操作

```json
{
  "operation": {
    "kind": "SET_DOMAIN_PROPERTIES",
    "objectName": "Z_EXAMPLE_DOMAIN",
    "transportRequest": "S4HK900001",
    "properties": {
      "typeInformation": {
        "datatype": "CHAR",
        "length": 20,
        "decimals": 0
      }
    }
  }
}
```

将该参数传给 `previewDdicPropertyChange`。确认返回的对象、字段差异、transport 和到期时间后，直接调用：

```json
{
  "operationPlanId": "预览返回的计划编号"
}
```

对应工具为 `applyDdicPropertyChange`。确认接受后，服务重新读取当前属性并检查漂移，再按既定锁、写入、解锁、激活和复读路径执行。远端写入最多一次；只有写入结果明确且后续步骤失败时，才会尝试一次受控恢复。恢复失败或结果不确定时停止自动操作。

### 11.2 开发包迁移

先调用 `previewPackageChange`：

```json
{
  "objectType": "CLASS",
  "objectName": "ZCL_EXAMPLE",
  "oldPackage": "ZOLD",
  "newPackage": "ZNEW",
  "transportRequest": "S4HK900001"
}
```

预览会冻结目标、旧包、新包、transport、影响对象和关键消息。审阅后将 `operationPlanId` 传给 `applyPackageChange`。确认接受后，服务重跑 preview 并比较关键字段；发生漂移时不 execute。迁移只执行一次，随后只读复查对象结构或包元数据。服务不会自动迁回旧包。

### 11.3 RAP 生成与服务发布

RAP 生成使用 `RAP_GENERATE`，输入包括受限 `genId`、参考对象、包、transport 和 content：

```json
{
  "operation": {
    "kind": "RAP_GENERATE",
    "genId": "uiservice",
    "referenceObjectName": "ZEXAMPLE_TABLE",
    "packageName": "ZEXAMPLE",
    "transportRequest": "S4HK900001",
    "content": {
      "general": { "description": "Example service" },
      "businessObject": {
        "dataModelEntity": { "cdsName": "ZI_EXAMPLE" },
        "behavior": {
          "implementationType": "managed",
          "implementationClass": "ZBP_I_EXAMPLE",
          "draftTable": "ZEXAMPLE_D"
        }
      },
      "serviceProjection": { "name": "ZC_EXAMPLE" },
      "businessService": {
        "serviceDefinition": { "name": "ZUI_EXAMPLE" },
        "serviceBinding": {
          "name": "ZUI_EXAMPLE_O4",
          "bindingType": "OData V4 - UI"
        }
      }
    }
  }
}
```

服务发布使用独立计划：

```json
{
  "operation": {
    "kind": "RAP_PUBLISH_SERVICE",
    "serviceBindingName": "ZUI_EXAMPLE_O4"
  }
}
```

两种操作都先调用 `previewRapOperation`，再把返回的 `operationPlanId` 传给 `applyRapOperation`。生成和发布必须分别预览、分别确认。服务在 apply 时重新校验 availability、validation、preview 和目标状态；生成或发布最多调用一次。生成后按对象清单只读复查，发布后只读检查可观察状态。服务不会自动删除部分生成对象、取消发布或重试未知结果。

### 11.4 未知结果处理

三组高级操作可能返回 `UNKNOWN_OUTCOME`。这不是成功或失败结论，而是服务无法从响应和只读证据证明远端状态。此时禁止重复调用 apply，也不要直接创建相同的新计划。先使用 `getDomainProperties`、`getDataElementProperties`、`getTextElements`、`objectStructureElements`、`changePackagePreview`、`rapGenIsAvailable` 或其他适用的只读工具核验当前状态，再把证据交给用户决定后续动作。

## 12. DEV 安全调试操作

本节只适用于 `SAP_MCP_TOOL_PROFILE=development-workbench` 且 `SAP_MCP_SYSTEM_ROLE=DEV` 的 `sap-dev` 实例。QAS/PRD 运维别名使用 `operations-readonly`，只能调用 `debuggerListeners`、`debuggerStackTrace`、`debuggerVariables`、`debuggerChildVariables` 等已有现场读取工具。

### 12.1 创建监听器、设置断点和 Attach

所有监听器、断点、Attach 和设置变更先调用 `previewDebugOperation`。例如预览 Attach：

```json
{
  "operation": {
    "kind": "ATTACH",
    "debuggingMode": "user",
    "debuggeeId": "明确选中的 debuggee ID",
    "targetUser": "DEVUSER",
    "dynproDebugging": false
  }
}
```

确认预览中的 host、client、用户、debuggee、摘要和风险后，调用：

```json
{
  "debugOperationPlanId": "preview 返回的计划编号"
}
```

对应工具为 `applyDebugOperation`。服务只接受原生 form 弹框，不接受 `textConfirmation`。用户取消、关闭或超时不会消费计划，也不会访问 SAP。Attach 成功后会撤销该用户此前的调试授权，并保存新的进程内 Attach 上下文。

监听器操作使用 `CREATE_LISTENER` 或 `DELETE_LISTENER`，包含 `debuggingMode`、`terminalId`、`ideId` 和 `targetUser`。断点操作使用 `SET_BREAKPOINTS` 或 `DELETE_BREAKPOINT`，单计划最多 50 个断点。保存设置使用 `SAVE_SETTINGS`，只接受 `systemDebugging`、`createExceptionObject`、`backgroundRFC`、`sharedObjectDebugging`、`showDataAging`、`updateDebugging` 六个布尔字段，不接收任意设置字符串。

### 12.2 授权并执行单次命令

Attach 成功后调用 `authorizeDebugSession`：

```json
{
  "targetUser": "DEVUSER",
  "debuggeeId": "与安全 Attach 相同的 debuggee ID"
}
```

原生确认接受后返回 `authorizationId`，默认 15 分钟有效。每次 Step 或 Continue 必须由用户发出一个明确工具调用：

```json
{
  "authorizationId": "当前授权编号",
  "targetUser": "DEVUSER",
  "command": {
    "command": "stepInto"
  }
}
```

`command` 只接受 `stepInto`、`stepOver`、`stepReturn`、`stepContinue`、`stepRunToLine` 或 `goToStack`。`stepRunToLine` 额外提供 `url`，`goToStack` 额外提供 `urlOrPosition`。每次只执行一个动作，完成后立即复读调用栈；不支持命令数组或自动循环。

### 12.3 跳转行、终止进程和变量修改

跳转到指定行和终止 debuggee 会改变控制流或事务状态，不能放进 `executeDebugCommand`。必须分别使用 `JUMP_TO_LINE` 或 `TERMINATE_DEBUGGEE` 创建计划，再由 `applyDebugOperation` 每次单独原生确认。计划必须绑定当前 `authorizationId`、`targetUser` 和 `debuggeeId`。

变量修改先调用 `previewDebugVariableChange`：

```json
{
  "authorizationId": "当前授权编号",
  "targetUser": "DEVUSER",
  "variableName": "LV_VALUE",
  "newValue": "计划的新值",
  "parents": ["@ROOT"]
}
```

预览会冻结当前栈帧、变量原值和目标值，但返回视图与审计只显示哈希和字节摘要。调用 `applyDebugVariableChange` 时只提交 `debugOperationPlanId`；服务打开新的原生弹框，然后复读栈帧和原值。栈帧或原值漂移、变量只读、变量不存在都会在调用 `debuggerSetVariableValue` 前拒绝。

### 12.4 状态、未知结果和清理

使用 `getDebugOperationStatus` 查询计划。`UNKNOWN` 或 `remote_result_unknown` 表示控制请求可能成功也可能失败；服务已经停止自动执行，只做监听器或调用栈等只读复查，调用方不得盲目重试同一动作。

调试结束后调用 `revokeDebugSession` 撤销授权，并按已确认计划删除监听器和断点。MCP 重启会自然清空全部计划、Attach 上下文和授权。当前八工具已通过 fake ADT 单元/状态机测试，真实 SAP DEV 控制动作尚未执行；任何现场验证都需要专用测试用户、可恢复测试程序和新的明确授权。

## 13. 失败与恢复

| 错误/状态 | 含义 | 操作 |
| --- | --- | --- |
| `SYNTAX_CHECK_FAILED` | 预览或写后语法错误。 | 修复完整源码并重新预览。 |
| `TRANSPORT_INVALID` | 传输不可用、已释放或格式错误。 | 在 SAP 中确认正确的已有未释放请求。 |
| `SOURCE_DRIFT` | 预览后 SAP 源码被修改。 | 重新读取当前源码并创建新计划。 |
| `INVALID_CREATION_GRAPH` | 创建对象组合、父对象字段或源码框架非法。 | 修正对象图后重新预览。 |
| `OBJECT_ALREADY_EXISTS` | 目标对象已存在。 | 改用源码修改流程或选择新的对象名；安全创建不会覆盖现有对象。 |
| `OBJECT_CREATION_FAILED` | ADT 创建失败或结果不确定。 | 查询创建计划并人工确认对象、锁和传输，禁止直接重试。 |
| `COMPENSATION_FAILED` | 创建失败后的反向删除不完整。 | 停止自动重试，按计划清单人工检查和清理。 |
| `PLAN_NOT_FOUND` | MCP 重启或计划不存在。 | 重新预览。 |
| `PLAN_EXPIRED` | 计划已过期。 | 重新预览。 |
| `PLAN_ALREADY_CONSUMED` | 计划已应用或已终结。 | 不可重用，重新预览。 |
| `LOCK_FAILED` | 对象被其他用户或会话锁定。 | 检查锁持有者；源码变化后必须重新预览。 |
| `CONFIRMATION_UNSUPPORTED` | 客户端无原生弹框且文字降级关闭。 | 换支持 form 的客户端，或显式启用文字降级。 |
| `ACTIVATION_FAILED` | 激活明确失败或远端结果无法确认。 | 源码修改查看是否进入 `ROLLED_BACK`；对象创建查看是否进入 `COMPENSATED` 或 `COMPENSATION_FAILED`。结果未知时停止重试并人工检查 active/inactive 对象。 |
| `VERIFY_FAILED` | 激活后内容存在非换行差异。 | 查看恢复状态并人工检查对象。 |
| `ROLLED_BACK` | 原源码已恢复、重新激活并复核。 | 本次变更未生效，解决原因后重新预览。 |
| `ROLLBACK_FAILED` | 自动恢复不完整。 | 停止自动重试，人工检查源码、非活动版本、锁和传输。 |
| `UNLOCK_FAILED` | 解锁失败。 | 停止自动重试，人工检查锁。 |
| `AUDIT_FAILED` | 审计目录不可写。 | 恢复目录权限后再尝试修改。 |
| `DEBUG_CONTEXT_MISSING` | 没有匹配的安全 Attach、栈帧或变量。 | 只读检查现场，重新 Attach 后再授权。 |
| `DEBUG_STATE_DRIFT` | 变量原值或栈帧在预览后变化。 | 放弃旧计划，按当前现场重新预览。 |
| `AUTHORIZATION_NOT_FOUND` / `AUTHORIZATION_EXPIRED` | 授权不存在、已撤销或超时。 | 重新确认当前 Attach 并申请新授权。 |
| `REMOTE_RESULT_UNKNOWN` | 超时或断线后无法确认调试控制结果。 | 只读复查现场，禁止盲目重放。 |
| `STATE_DRIFT` | 高级操作当前状态与 preview 冻结状态不同。 | 放弃旧计划，读取当前状态后重新预览。 |
| `VALIDATION_FAILED` | DDIC、包迁移或 RAP 的远端/本地校验失败。 | 修正输入或环境，不进入 apply。 |
| `UNKNOWN_OUTCOME` | 高级写入、迁移、生成或发布结果无法证明。 | 停止写入与重试，先做只读核验并人工决定。 |
| `429` | 工具执行队列已满。 | 等待当前 SAP 操作结束后重试。 |
| `413` | 响应超过字节限制。 | 缩小查询范围、减少字段或分批读取。 |

写操作发生 HTTP 超时时，远端结果可能已经成功，也可能失败。不要直接重试；先读取对象或计划状态，确认 SAP 实际结果。

## 14. 审计与运维

审计文件：

```text
<SAP_MCP_AUDIT_PATH>\abap-change-audit.jsonl
```

记录包括计划、对象、传输、阶段、哈希、匹配类型、回滚和解锁结果，以及安全调试的操作类型、目标用户、debuggee、计划/授权哈希和变量值哈希；不应包含完整源码、diff、变量完整值、密码、Cookie、锁句柄或确认短语。

服务不会自动轮转和删除审计日志。运行环境需要负责：

- 目录权限。
- 磁盘容量告警。
- 日志归档与保留周期。
- 审计文件访问控制。

## 15. `legacy-full` 使用边界

设置：

```env
SAP_MCP_TOOL_PROFILE=legacy-full
```

DEV 会注册全部 161 个工具，即七个安全源码工具、六个高层运行工具和 148 个原始低层 ADT 工具。安全调试、受控高级操作和质量检查使用 `development-workbench`，不会叠加到 `legacy-full`。低层工具包括写入、删除、传输、调试、DDIC、包迁移、RAP 和查询能力，不经过受控工作流。正式开发、业务排查和系统运维 Skill 不依赖此兼容 Profile。QAS/PRD/缺失或非法角色即使配置 `legacy-full`，也只会得到本地与只读子集。

除非现有客户端明确依赖，否则不要启用。启用时服务会在 stderr 输出警告。查询和搜索仍受统一数量、响应大小、超时和执行门控保护，但这些保护不能替代变更预览与人工确认。

## 16. 更新源码后的步骤

每次拉取或修改源码后：

```powershell
npm install
npm test -- --runInBand
npm run build
git diff --check
```

然后完整重启 MCP 客户端，使新的 `dist` 和 `.env` 生效。

如果只修改 `.env`，也必须重启客户端；环境变量只在 MCP 进程启动时读取。
