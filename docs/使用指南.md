# mcp-abap-abap-adt-api 使用指南

## 1. 当前分发状态

截至 2026-08-12，当前修改版尚未发布到 npm 或 MCP Registry，也没有可从 FLUJO Marketplace 直接安装的现役包。

正确使用方式是：先取得确实包含当前改动的源码目录，在该目录安装依赖、构建 `dist`，再让 Codex、Claude 或其他 MCP 客户端通过 `node` 启动 `dist/index.js` 的绝对路径。当前改动尚未通过正式 Release 分发，不能假定重新克隆上游仓库会包含本文描述的版本。

`package.json` 和 `server.json` 中保留 npm/Registry 元数据，是为了未来可能发布，不代表当前已经上线。

## 2. 使用前准备

需要满足：

- Windows 上已安装 Node.js 18 或更高版本和 npm。
- SAP ABAP 开发系统可通过 ADT 访问。
- `SICF` 中已启用 `/sap/bc/adt`。
- SAP 用户具备目标对象、语法检查、锁定、激活和传输请求所需权限。
- 安全修改对象属于允许的 `Z`/`Y` 命名空间，并位于可传输包中，不能是 `$TMP`。
- 使用一个已有、未释放且 SAP 报告为目标对象可用的十位传输请求。

在项目目录执行：

```powershell
node -v
npm -v
npm install
Copy-Item .env.example .env
npm run build
```

项目当前路径示例：

```text
D:\MyDev\SAP\mcp-abap-abap-adt-api
```

## 3. 配置 `.env`

不要把 `.env` 提交到 Git，也不要在聊天、日志或截图中公开密码。

最小安全配置：

```env
SAP_URL=https://your-sap-server.com:44300
SAP_USER=YOUR_SAP_USERNAME
SAP_PASSWORD=YOUR_SAP_PASSWORD
SAP_CLIENT=100
SAP_LANGUAGE=ZH

SAP_MCP_TOOL_PROFILE=safe
SAP_MCP_SYSTEM_ROLE=DEV
SAP_MCP_ALLOWED_HOSTS=your-sap-server.com
SAP_MCP_ALLOWED_CLIENTS=100
SAP_MCP_ALLOWED_NAMESPACES=Z,Y
SAP_MCP_CHANGE_PLAN_TTL_SECONDS=900
SAP_MCP_AUDIT_PATH=D:\sap-mcp-audit
SAP_MCP_ALLOW_TEXT_CONFIRMATION=false
```

说明：

- `SAP_MCP_TOOL_PROFILE=safe`：默认只开放七个高层受控工具，包括源码修改和对象创建。
- `SAP_MCP_SYSTEM_ROLE=DEV`：源码访问和修改只允许显式标记为 DEV 的系统。
- `SAP_MCP_ALLOWED_HOSTS`：填写 `SAP_URL` 中的主机名，不含协议和端口。
- `SAP_MCP_ALLOWED_CLIENTS`：三位客户端号，可以用逗号配置多个。
- `SAP_MCP_ALLOWED_NAMESPACES`：允许的对象名前缀，默认建议仅 `Z,Y`。
- `SAP_MCP_CHANGE_PLAN_TTL_SECONDS`：计划有效期，范围 60–3600 秒，当前建议 900 秒。
- `SAP_MCP_AUDIT_PATH`：MCP 进程必须有写权限；安全修改在审计不可写时关闭失败。
- `SAP_MCP_ALLOW_TEXT_CONFIRMATION=false`：优先使用原生 MCP 弹框。只有客户端不支持 form elicitation 时，才考虑显式启用文字降级。

如果开发系统使用自签名证书，可在受控开发环境增加：

```env
NODE_TLS_REJECT_UNAUTHORIZED=0
```

这会关闭 Node.js TLS 证书校验，不建议在生产或不受控网络使用。

## 4. 性能与资源配置

`.env.example` 已提供推荐默认值：

| 环境变量 | 默认值 | 范围 | 作用 |
| --- | ---: | --- | --- |
| `SAP_MCP_ADT_TIMEOUT_MS` | `60000` | 5000–600000 | ADT HTTP 请求超时。 |
| `SAP_MCP_MAX_CONCURRENT_TOOLS` | `1` | 1–8 | 同时访问共享 ADT 会话的工具数量。 |
| `SAP_MCP_MAX_QUEUED_TOOLS` | `50` | 0–1000 | FIFO 等待队列容量。 |
| `SAP_MCP_QUERY_DEFAULT_ROWS` | `200` | 1–查询上限 | `tableContents`、`runQuery` 默认行数。 |
| `SAP_MCP_QUERY_MAX_ROWS` | `5000` | 1–100000 | 查询行数硬上限。 |
| `SAP_MCP_SEARCH_DEFAULT_RESULTS` | `50` | 1–搜索上限 | `searchObject` 默认数量。 |
| `SAP_MCP_SEARCH_MAX_RESULTS` | `500` | 1–10000 | 搜索结果硬上限。 |
| `SAP_MCP_MAX_ARGUMENT_BYTES` | `5242880` | 64 KiB–50 MiB | 单次工具参数的 UTF-8 JSON 字节上限，包含完整源码。 |
| `SAP_MCP_MAX_RESPONSE_BYTES` | `10485760` | 1–100 MiB | 单个工具文本响应上限。 |
| `SAP_MCP_SOURCE_CACHE_MAX_ENTRIES` | `20` | 0–1000 | 会话源码缓存数量，`0` 关闭。 |
| `SAP_MCP_SOURCE_CACHE_MAX_ITEM_BYTES` | `2097152` | 64 KiB–20 MiB | 单份缓存源码上限。 |
| `SAP_MCP_SOURCE_CACHE_TTL_SECONDS` | `900` | 60–3600 | 源码缓存有效期。 |
| `SAP_MCP_CHANGE_PLAN_MAX_ENTRIES` | `100` | 1–1000 | 内存计划记录上限。 |
| `SAP_MCP_ROLLBACK_FAILED_RETENTION_SECONDS` | `86400` | 3600–604800 | 回滚失败时恢复数据保留期。 |
| `SAP_MCP_LOG_LEVEL` | `warn` | `error/warn/info/debug` | 普通 stderr 日志级别。 |

建议保持 `SAP_MCP_MAX_CONCURRENT_TOOLS=1`。当前 ADTClient 是共享的有状态会话，并发调用可能导致 Cookie、CSRF、会话类型和锁生命周期交叉。提高并发前必须在专用 SAP DEV 环境重新验证。

所有配置在启动时严格校验。越界或默认值大于上限会导致服务拒绝启动，并指出具体变量。

## 5. 接入 Codex

以下结构已在当前本机 Codex 配置中实际使用。不同 Codex 版本的配置入口可能变化；如果界面支持添加本地 MCP，也可以用相同的 `command`、`args` 表达。

在 Codex 的 `config.toml` 增加：

```toml
[mcp_servers.abap_adt_safe]
enabled = true
startup_timeout_sec = 120
command = 'C:\path\to\node.exe'
args = ['D:\MyDev\SAP\mcp-abap-abap-adt-api\dist\index.js']
```

说明：

- Windows 路径建议使用 TOML 单引号，减少反斜杠转义。
- SAP 凭据保存在项目 `.env`，不要重复写进全局 Codex 配置。
- 修改 `.env`、源码、`dist` 或 `config.toml` 后，需要完整重启 Codex。
- 重启后确认工具列表只有 `inspectAbapObject`、`previewAbapChange`、`applyAbapChange`、`getAbapChangeStatus`、`previewAbapObjectCreation`、`applyAbapObjectCreation`、`getAbapObjectCreationStatus`，证明当前处于 `safe` 模式。

## 6. 接入 Claude 或其他 JSON 配置客户端

通用 stdio 配置示例：

```json
{
  "mcpServers": {
    "abap_adt_safe": {
      "command": "C:\\path\\to\\node.exe",
      "args": [
        "D:\\MyDev\\SAP\\mcp-abap-abap-adt-api\\dist\\index.js"
      ]
    }
  }
}
```

客户端版本不同，配置文件位置和外层字段可能不同，但核心必须是本机 `node.exe` 加本项目 `dist/index.js` 绝对路径，而不是 `npx mcp-abap-abap-adt-api`。

客户端支持 MCP `elicitation.form` 时会使用原生确认弹框。客户端不支持时：

- `SAP_MCP_ALLOW_TEXT_CONFIRMATION=false`：只能读取和预览，应用返回 `CONFIRMATION_UNSUPPORTED`。
- `SAP_MCP_ALLOW_TEXT_CONFIRMATION=true`：第一次应用返回一次性确认短语，用户明确同意后用完全一致的 `textConfirmation` 再调用一次。

文字确认无法证明消息一定由人输入，安全性低于原生弹框。

先验证代码：

```powershell

```


该命令独立启动当前 `dist/index.js`，临时使用 `legacy-full`，但脚本自身只允许调用 `searchObject`、`tableContents` 和 `getObjectSource`。它不会修改项目 `.env`，不会锁定、写入或激活 SAP 对象，也不会输出表内容。测试对象和系统表固定为 `ZCODEX_MCP_TEST`、`ZCODEX_MCP_TEST_I01`、`TSTC`、`TSTCT`、`DD02L` 和 `DD03L`；在其他环境运行前应先复核这些读取目标。

完整缓存 TTL 测试额外等待 61 秒：

```powershell

```

不访问 SAP 的真实 HTTP 取消验证：

```powershell
npm run test:adt-timeout
```

该命令让底层 ADT 客户端访问本机停滞端点，验证 `5000 ms` 超时是否真正取消请求。它不会使用 `.env` 中的 SAP 地址发起测试请求。

1. 确认 MCP 服务加载成功。
2. 确认 `safe` 模式只显示七个高层工具。
3. 使用 `inspectAbapObject` 读取一个白名单内的专用测试对象。
4. 核对返回的对象类型、名称、包、源码和 `sourceHash`。

只读检查通过并不代表写入权限、传输请求和激活流程已经可用。

## 8. 安全修改操作

### 第一步：读取当前源码

调用：

```text
inspectAbapObject
```

参数：

```json
{
  "objectType": "PROGRAM",
  "objectName": "ZYOUR_TEST_PROGRAM"
}
```

支持的 `objectType`：

- `PROGRAM`
- `INCLUDE`
- `CLASS`
- `FUNCTION_MODULE`

必须以返回的完整源码作为后续编辑基线，不要只提交局部片段。

### 第二步：预览完整修改

调用：

```text
previewAbapChange
```

参数：

```json
{
  "objectType": "PROGRAM",
  "objectName": "ZYOUR_TEST_PROGRAM",
  "newSource": "完整的目标 ABAP 源码",
  "transportRequest": "DEVK900001"
}
```

预览阶段会：

1. 校验 DEV、主机、客户端和命名空间策略。
2. 精确解析目标 ADT 对象。
3. 确认对象不在 `$TMP`。
4. 确认传输请求是十位且 SAP 报告为对象可用、未释放。
5. 读取当前源码并生成原始哈希。
6. 检查完整目标源码语法。
7. 返回完整 diff 和短时 `changePlanId`。

预览不会锁定、写入或激活 SAP 对象。

### 第三步：审阅 diff

人工确认至少包括：

- 对象类型和对象名正确。
- 传输请求正确。
- diff 只包含预期修改。
- 没有删除必要声明、Include 或方法实现。
- 没有凭据、测试后门或无边界数据访问。

如果 diff 不正确，不要应用；修改完整目标源码后重新预览。

### 第四步：应用计划

调用：

```text
applyAbapChange
```

参数：

```json
{
  "changePlanId": "preview 返回的计划编号"
}
```

支持原生 form elicitation 的客户端会显示：

- `应用变更`
- `取消`

选择取消、点击跳过、关闭弹框、未选择或等待超时都不会写入 SAP。超时后计划仍保持 `PREVIEWED`；计划有效期内可再次调用应用重新弹框。

确认应用后，服务按顺序执行：

1. 再次验证传输请求。
2. 复读 SAP 源码并检查是否发生漂移。
3. 获取 `MODIFY` 锁。
4. 写入计划绑定的完整目标源码。
5. 再次执行语法检查。
6. 解锁。
7. 激活对象。
8. 复读激活后的源码并校验。

源码验证允许 SAP 仅规范化 `CRLF`、`LF`、单独 `CR` 和文件末尾换行；这种情况记录为 `LINE_ENDING_NORMALIZED`。空格、Tab、注释、大小写或任何其他字符差异仍为 `DIFFERENT`，并触发失败恢复。

### 第五步：检查结果

成功结果应满足：

- 计划状态为 `APPLIED`。
- `SOURCE_VERIFIED` 阶段成功。
- `sourceMatchType` 为 `EXACT` 或 `LINE_ENDING_NORMALIZED`。
- `unlockSucceeded=true`。

需要详细阶段时调用：

```json
{
  "changePlanId": "计划编号"
}
```

对应工具为 `getAbapChangeStatus`。

## 9. 安全创建对象

对象创建仍采用“预览计划 → 用户确认 → 应用计划 → 查询状态”，不能直接把 `confirmedByUser` 作为参数传入。

首期支持以下对象图：

- 单个 `PROGRAM`。
- 单个 `FUNCTION_GROUP`。
- 单个 `FUNCTION_MODULE`，父函数组必须已经存在。
- 一个新 `FUNCTION_GROUP`，紧接其首个 `FUNCTION_MODULE`。

首期不维护函数模块的导入、导出、更改、表和异常参数，也不创建或释放传输请求。函数组源码及 `L<函数组>TOP`、`L<函数组>UXX` 等 Include 由 SAP 生成，调用方不能提交函数组源码。

### 第一步：预览创建

调用 `previewAbapObjectCreation`。以下示例是带注释的 JSONC，不是严格 JSON。

创建程序：

```jsonc
{
  "objects": [{
    "objectType": "PROGRAM",
    "objectName": "ZYOUR_NEW_PROGRAM",
    "description": "受控创建测试程序",
    "packageName": "ZYOUR_PACKAGE",
    // 必须提交完整源码，且名称与 objectName 一致。
    "source": "REPORT zyour_new_program.\nWRITE / 'Created by safe workflow'."
  }],
  "transportRequest": "DEVK900001"
}
```

在已有函数组中创建函数模块：

```jsonc
{
  "objects": [{
    "objectType": "FUNCTION_MODULE",
    "objectName": "ZYOUR_NEW_FM",
    "description": "受控创建测试函数",
    "parentFunctionGroup": "ZYOUR_EXISTING_FG",
    // 首期不接受 packageName；包由父函数组确定。
    "source": "FUNCTION zyour_new_fm.\nENDFUNCTION."
  }],
  "transportRequest": "DEVK900001"
}
```

创建新函数组及首个函数模块：

```jsonc
{
  "objects": [
    {
      "objectType": "FUNCTION_GROUP",
      "objectName": "ZYOUR_NEW_FG",
      "description": "受控创建测试函数组",
      "packageName": "ZYOUR_PACKAGE"
      // 不允许 source，函数池和标准 Include 由 SAP 生成。
    },
    {
      "objectType": "FUNCTION_MODULE",
      "objectName": "ZYOUR_NEW_FM",
      "description": "新函数组的首个函数模块",
      "parentFunctionGroup": "ZYOUR_NEW_FG",
      "source": "FUNCTION zyour_new_fm.\nENDFUNCTION."
    }
  ],
  "transportRequest": "DEVK900001"
}
```

预览会验证策略、对象图、父对象、目标不存在、包和传输，并调用可执行的 ADT 名称校验。新函数组尚不存在时，其子函数模块的 ADT 名称校验会明确延迟到应用阶段、父函数组创建成功之后。预创建语法检查也会延迟，因为目标源码 URL 尚不存在。

### 第二步：确认并应用

调用 `applyAbapObjectCreation`：

```json
{
  "creationPlanId": "预览返回的计划编号"
}
```

原生确认弹框会列出对象图和传输请求。客户端不支持弹框且显式启用了文字降级时，第一次调用会返回一次性中文确认短语，第二次必须原样提交。

应用会重新验证策略、传输和目标不存在，再按依赖顺序创建。程序和函数模块会执行锁定、整段源码写入、语法检查、解锁、激活和复读；函数组只验证 SAP 生成的对象和源码链接，不覆盖函数池源码。

创建不是数据库事务。失败时服务按反向依赖顺序删除当前计划已经证明归属的对象；若创建请求结果不确定、对象身份无法证明或删除失败，服务停止自动恢复并将计划置为 `COMPENSATION_FAILED`，必须人工检查 SAP 对象、锁和传输，禁止盲目重试。

### 第三步：查询状态

调用 `getAbapObjectCreationStatus`：

```json
{
  "creationPlanId": "创建计划编号"
}
```

成功状态为 `APPLIED`。失败后重点检查 `createdObjects`、`ownershipProven`、`compensationAttempted` 和 `compensationSucceeded`。

## 10. 失败与恢复

| 错误/状态 | 含义 | 操作 |
| --- | --- | --- |
| `SYNTAX_CHECK_FAILED` | 预览或写后语法错误。 | 修复完整源码并重新预览。 |
| `TRANSPORT_INVALID` | 传输不可用、已释放或格式错误。 | 在 SAP 中确认正确的已有未释放请求。 |
| `SOURCE_DRIFT` | 预览后 SAP 源码被修改。 | 重新读取当前源码并创建新计划。 |
| `PLAN_NOT_FOUND` | MCP 重启或计划不存在。 | 重新预览。 |
| `PLAN_EXPIRED` | 计划已过期。 | 重新预览。 |
| `PLAN_ALREADY_CONSUMED` | 计划已应用或已终结。 | 不可重用，重新预览。 |
| `LOCK_FAILED` | 对象被其他用户或会话锁定。 | 检查锁持有者；源码变化后必须重新预览。 |
| `INVALID_CREATION_GRAPH` | 创建对象组合、父对象字段或源码框架非法。 | 修正对象图后重新预览。 |
| `OBJECT_ALREADY_EXISTS` | 目标对象已存在。 | 改用源码修改流程或选择新的对象名；安全创建不会覆盖现有对象。 |
| `OBJECT_CREATION_FAILED` | ADT 创建失败或结果不确定。 | 查询创建计划并人工确认对象、锁和传输，禁止直接重试。 |
| `COMPENSATION_FAILED` | 创建失败后的反向删除不完整。 | 停止自动重试，按计划清单人工检查和清理。 |
| `CONFIRMATION_UNSUPPORTED` | 客户端无原生弹框且文字降级关闭。 | 换支持 form 的客户端，或显式启用文字降级。 |
| `ACTIVATION_FAILED` | 激活失败。 | 查看计划是否自动进入 `ROLLED_BACK`。 |
| `VERIFY_FAILED` | 激活后内容存在非换行差异。 | 查看恢复状态并人工检查对象。 |
| `ROLLED_BACK` | 原源码已恢复、重新激活并复核。 | 本次变更未生效，解决原因后重新预览。 |
| `ROLLBACK_FAILED` | 自动恢复不完整。 | 停止自动重试，人工检查源码、非活动版本、锁和传输。 |
| `UNLOCK_FAILED` | 解锁失败。 | 停止自动重试，人工检查锁。 |
| `AUDIT_FAILED` | 审计目录不可写。 | 恢复目录权限后再尝试修改。 |
| `429` | 工具执行队列已满。 | 等待当前 SAP 操作结束后重试。 |
| `413` | 响应超过字节限制。 | 缩小查询范围、减少字段或分批读取。 |

写操作发生 HTTP 超时时，远端结果可能已经成功，也可能失败。不要直接重试；先读取对象或计划状态，确认 SAP 实际结果。

## 11. 审计与运维

审计文件：

```text
<SAP_MCP_AUDIT_PATH>\abap-change-audit.jsonl
```

记录包括计划、对象、传输、阶段、哈希、匹配类型、回滚和解锁结果；不应包含完整源码、diff、密码、Cookie、锁句柄或确认短语。

服务不会自动轮转和删除审计日志。运行环境需要负责：

- 目录权限。
- 磁盘容量告警。
- 日志归档与保留周期。
- 审计文件访问控制。

## 12. `legacy-full` 使用边界

设置：

```env
SAP_MCP_TOOL_PROFILE=legacy-full
```

会额外开放原始低层 ADT 工具，包括写入、删除、传输、调试和查询能力。这些工具不经过七工具安全工作流。

除非现有客户端明确依赖，否则不要启用。启用时服务会在 stderr 输出警告。查询和搜索仍受统一数量、响应大小、超时和执行门控保护，但这些保护不能替代变更预览与人工确认。

## 13. 更新源码后的步骤

每次拉取或修改源码后：

```powershell
npm install
npm test -- --runInBand
npm run build
git diff --check
```

然后完整重启 MCP 客户端，使新的 `dist` 和 `.env` 生效。

如果只修改 `.env`，也必须重启客户端；环境变量只在 MCP 进程启动时读取。

## 13. 已验证与未验证边界

已验证：

- 四类对象的真实 SAP DEV 成功流程。
- 原生弹框应用、取消、关闭和超时。
- 语法拒绝、锁冲突、源码漂移、计划重启失效、自然过期和重复消费。
- 可控激活失败后的真实自动回滚、重新激活、哈希复核和无残留锁。
- `LINE_ENDING_NORMALIZED` 的真实 SAP DEV 成功路径。
- 查询/搜索上限、搜索默认数量、响应 `413`、源码缓存命中/LRU/TTL，以及同进程 FIFO 和队列满 `429` 的真实 SAP DEV 只读烟测。
- 底层 ADT HTTP `5000 ms` 超时通过本机停滞端点端到端验证。
- 22 个测试套件、160 项自动化测试、TypeScript 构建和差异检查。

仍需运行环境确认：

- 调试、ATC、trace 等长任务的实际专用超时和取消行为。
- 将 `SAP_MCP_MAX_CONCURRENT_TOOLS` 提高到大于 `1` 后，共享 Cookie、CSRF、会话类型和锁生命周期是否安全。
- 超过 64 KiB 的真实大源码不缓存行为，以及 `legacy-full` 直接写入后的缓存更新；默认安全流程不依赖该低层写入验证。
- 不同 SAP 版本、不同权限模型和生产部署表现。

出现上述未验证场景时，应先在专用 DEV 对象和测试传输上验证，不要直接推到生产。
