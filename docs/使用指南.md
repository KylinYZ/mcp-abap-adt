# mcp-abap-abap-adt-api 使用指南

更新时间：2026-09-04。本文是安装、配置和安全操作入口；逐类创建证据与历史过程不在此复制。

## 1. 产品入口与版本

当前版本为 `0.6.0`，npm 包为 `@kylinyz/mcp-abap-abap-adt-api@0.6.0`。新安装按角色选择：

| 入口 | 等价 profile | 工具数 | 适用角色 |
| --- | --- | ---: | --- |
| `focused` / `developer` | `development-workbench` | 90 | 开发人员 |
| `business` | `business-readonly` | 18 | 业务顾问 |
| `operations` | `operations-readonly` | 41 | 运维人员 |
| `expert` | `legacy-full` | 161 | 专家和旧脚本 |

`safe`、`development`、`diagnostic-readonly` 等旧名称继续兼容。完整定位见 [`产品定位.md`](产品定位.md)。

## 2. 前置条件

- Node.js 18+、npm，以及可通过 ADT 访问的 SAP ABAP 系统。
- SAP 已启用 `/sap/bc/adt`，用户具备目标操作所需权限。
- 写操作使用允许的命名空间、可传输包和已有未释放传输请求。
- QAS、PRD、缺失和未知系统角色始终只读。

## 3. 安装与配置

### npm（推荐）

```powershell
npx -y @kylinyz/mcp-abap-abap-adt-api@0.6.0
```

### 源码

```powershell
npm install
npm run build
node dist/index.js
```

将 `.env.example` 复制到仓库外的私有路径，通过 `SAP_MCP_ENV_FILE` 指定。至少配置：

```env
SAP_URL=https://your-sap-server.example:44300
SAP_USER=YOUR_SAP_USERNAME
SAP_PASSWORD=YOUR_SAP_PASSWORD
SAP_CLIENT=100
SAP_MCP_TOOL_PROFILE=focused
SAP_MCP_SYSTEM_ROLE=DEV
SAP_MCP_ALLOWED_HOSTS=your-sap-server.example
SAP_MCP_ALLOWED_CLIENTS=100
SAP_MCP_ALLOWED_NAMESPACES=Z,Y
SAP_MCP_AUDIT_PATH=D:\sap-mcp-audit
```

生产环境可使用 `SAP_MCP_CREDENTIAL_COMMAND` / `SAP_MCP_CREDENTIAL_TARGET`，避免把密码写入环境文件。不要提交 `.env` 或凭据。

常用护栏：`SAP_MCP_MAX_CONCURRENT_TOOLS=1`、`SAP_MCP_ADT_TIMEOUT_MS=60000`、`SAP_MCP_QUERY_MAX_ROWS=5000`、`SAP_MCP_SEARCH_MAX_RESULTS=500`、`SAP_MCP_MAX_ARGUMENT_BYTES=5242880`、`SAP_MCP_MAX_RESPONSE_BYTES=10485760`。所有变量的范围见 `.env.example`。

## 4. 工具与安全流程

### 4.1 五分钟上手

新安装使用 `focused`（开发）入口时，推荐按下面顺序调用：

1. `sapDoctor`：一次检查本地配置和 SAP ADT capability；出现 `CHECK_REQUIRED` 时先按 `nextSteps` 修复。
2. `sap`，`action=help`：查看任务动作和参数示例。
3. `sap`，`action=read`：读取一个完整对象，例如 `params={"objectType":"CLASS","objectName":"ZCL_EXAMPLE"}`。
4. `sap`，`action=search` 或 `action=diagnose`：搜索对象，或从系统能力/运行 Dump 开始排查。
5. 需要修改或创建时使用 `sap` 的 `action=edit` / `action=create` 生成预览；真正应用仍使用服务端返回的 plan ID 和原有确认流程。

`sap` 是任务分流入口，不会创造新的 SAP 写入协议；每个动作最终仍调用现有工具，因此旧工具和旧脚本可以继续使用。`sapDoctor` 只读，不会创建、修改、激活或删除 SAP 对象。

源码修改必须依次执行：

1. `inspectAbapObject` 读取完整源码和元数据。
2. `previewAbapChange` 生成完整 diff 与服务器计划。
3. 审阅 diff，直接用 `changePlanId` 调用 `applyAbapChange`。
4. 用 `getAbapChangeStatus` 检查语法、激活、哈希和解锁。

仓库对象创建使用 `list/describe/preview/apply/status` 五个受控工具；cleanup 是独立的三工具流程。所有 apply 都由服务端发起一次原生确认，不接受调用方确认布尔值、任意 URL、XML/JSON、媒体类型或 lock handle。

远端结果不明确、锁状态不明确或源码漂移时立即停止；先只读核验，再用新 plan。历史 `OUTCOME_UNKNOWN`、`COMPENSATED` 和 `COMPENSATION_FAILED` 计划不可重放。

## 6. 重启与验证

修改源码、配置或 `dist` 后完整重启 MCP 客户端。新 session 应能通过 `healthcheck` 识别正确的 host/client/profile；旧 plan 应返回 `PLAN_NOT_FOUND`。

本地门禁：

```powershell
npm test -- --runInBand
npm run build
npm run check:repository-creation-coverage
git diff --check
```

构建后可运行 `npm run test:focused-entrypoint` 做本地 MCP stdio 冒烟。该测试只验证 `initialize`、`tools/list` 和 `sap(action=help)`，使用虚拟 SAP 地址，不访问真实 SAP。

在明确授权的 DEV 环境中，可运行 `npm run test:focused-real-dev:readonly -- "C:\\path\\to\\sap-dev.env"` 验证 `sapDoctor`、`sap(read)`、`sap(search)` 和 `sap(diagnose)`。该脚本只读，不输出源码、业务行或凭据。

源码预览可运行 `npm run test:focused-real-dev:preview -- "C:\\path\\to\\sap-dev.env" ZCODEX_MCP_TEST S4HK900009`。脚本先读取完整源码，再追加一行注释生成 preview，验证语法、传输、diff 和 `PREVIEWED` 计划；它不会调用 apply，不会锁定、写入或激活对象。预览计划会随 MCP 进程结束而失效。

自动化基线（2026-09-04）：109 个 Jest suites、793 个 tests。真实 SAP smoke 只在明确授权和专用 DEV 配置下运行。

## 7. 故障处理

- `PLAN_NOT_FOUND`、`PLAN_EXPIRED`、`PLAN_ALREADY_CONSUMED`：重新 preview。
- `SOURCE_DRIFT`：重新读取源码并 preview，不覆盖人工修改。
- `CONFIRMATION_UNSUPPORTED`：改用支持 MCP form 的客户端，或明确启用较弱的文字降级。
- `ROLLBACK_FAILED`、`UNLOCK_FAILED` 或未知远端结果：停止自动重试，人工检查 SAP 对象、锁、非活动版本和传输。
- npm 解析失败：确认使用带作用域的固定 `@kylinyz/mcp-abap-abap-adt-api@0.6.0`，不要使用不带作用域的上游包或 `@latest`。
